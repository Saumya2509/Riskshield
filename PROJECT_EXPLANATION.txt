================================================================================
RISKSHIELD — FULL PROJECT EXPLANATION
(Every module, function, and screen in small-to-small detail)
================================================================================

This file explains the RiskShield project as it exists in the riskshield/
folder. It is a front-end demo (React + Vite + TypeScript). There is no
real bank, no real database, and no real machine-learning server. All
matching, scoring, tax, cash forecast, and “AI” answers run in the browser
as deterministic JavaScript.


--------------------------------------------------------------------------------
1. WHAT THE PRODUCT IS
--------------------------------------------------------------------------------

RiskShield is a finance “controller” prototype. A controller’s job in a
company is to make sure money on the bank statement, money in the general
ledger, and money on invoices all agree.

A user (or the demo itself) feeds three kinds of records:

  BANK     — what actually hit the bank account (wires, ACH, deposits)
  LEDGER   — what the books say should have happened (golden source)
  INVOICE  — what was billed to/from a customer or vendor

The app then:

  1. Matches bank + invoice rows to ledger rows (3-pass engine).
  2. Flags exceptions (missing refs, duplicates, FX, short pays, orphans).
  3. Scores each record for “anomaly / risk” with a weighted formula.
  4. Maps matched rows to tax categories and estimated tax.
  5. Builds a 7-day cash forecast from cleared vs open amounts.
  6. Answers English questions about the current batch (keyword Q&A).
  7. Shows all of that on a landing site + dashboard + workbenches.

Typical user journey:

  Landing page  →  Dashboard  →  Reconciliation (load CSV or a 500-row
  demo batch)  →  Exceptions / Record details / Cash forecast / Reports /
  AI Assistant.


--------------------------------------------------------------------------------
2. HOW TO RUN IT
--------------------------------------------------------------------------------

Folder:   riskshield/
Command:  npm install
          npm run dev

Scripts in package.json:

  npm run dev      — Vite development server
  npm run build    — TypeScript check (tsc -b) then production bundle
  npm run preview  — Serve the production build
  npm run lint     — ESLint

Dependencies: React 19, React DOM 19.
Dev tools: Vite 6, TypeScript 5.8, ESLint, @vitejs/plugin-react.

vite.config.ts only enables the React plugin. There is no proxy, no API
base URL, no backend.

index.html is the single HTML shell. src/main.tsx mounts <App /> into
<div id="root"> inside React StrictMode (which double-invokes some
effects in development to catch bugs).

4. ROUTING — App.tsx
--------------------------------------------------------------------------------

There is no React Router. The app uses the URL hash:

  #/                  landing
  #/dashboard         dashboard
  #/reconciliation    (also #/finance)  reconciliation page
  #/exceptions        exceptions
  #/record-details    one record (optional ?id=BNK-001 style param)
  #/cash-forecast     cash forecast
  #/reports           reports
  #/ai-assistant      AI assistant
  #/settings          settings

Function currentView():
  Reads window.location.hash (lowercased).
  Checks prefixes in order (reconciliation/finance first, landing last).
  Returns a View union type.

Component App():
  useState(currentView) so first paint matches the current hash.
  useEffect adds a hashchange listener that calls setView(currentView()).
  Cleanup removes the listener.
  Wraps all pages in <FinanceContextProvider>.
  Renders exactly one page component based on view.

That means: changing the hash (sidebar links, <a href="#/...">) is enough
to switch screens. Shared reconciliation results survive the switch
because they live in FinanceContext, not in a single page’s local state.

5. SHARED STATE — FinanceContext.tsx
--------------------------------------------------------------------------------

Purpose: one place so Dashboard, Exceptions, Reports, AI, Record Details
all see the same last run.

Context fields (typical):

  report            ReconciliationReport | null
  mlResult          MLBatchResult | null
  lastRunAt         Date | null
  activeFileName    string | null     (which CSV / batch was used)
  recordCount       number
  setReport(r)      stores report AND stamps lastRunAt = now
  setMLResult(r)    stores ML batch result
  setActiveFileName
  setRecordCount
  resetReconciliation()  clears report, ML, filename, lastRunAt

FinanceContextProvider:
  Holds the useState values and passes them through Context.Provider.

useFinanceContext() / useFinanceContext():
  Thin wrapper around useContext(FinanceContext).

Default context values are no-ops (empty setters) so TypeScript is happy
if a component is rendered outside the provider (it should not be).

6. THE DATA MODEL — financeData.ts
--------------------------------------------------------------------------------

6.1 Types

  LedgerSource = 'BANK' | 'LEDGER' | 'INVOICE'
  Currency     = 'INR' | 'USD' | 'EUR' | 'GBP'
  EntryType    = 'CREDIT' | 'DEBIT'
  Category     = Accounts Receivable | SaaS Revenue | Consulting |
                 License Revenue | Enterprise Contract | Support Fees |
                 Project Payment | Wire Transfer | Vendor Payment | Services

  FinanceRecord {
    id            unique id, e.g. BNK-001, LDG-016, INV-019, B1-BNK-042
    source        BANK / LEDGER / INVOICE
    referenceId   payment / invoice reference (blank = MISSING_REF case)
    counterparty  customer or vendor name
    amount        number
    currency
    date          YYYY-MM-DD
    description
    type          CREDIT (money in) or DEBIT (money out)
    category
  }

6.2 Built-in 60-record demo

  20 ledger + 20 bank + 20 invoice rows, designed so every match pass
  and every exception type appears:

  Pass 1 Exact:
    BNK-001…015 match LDG-001…015 (same ref, amount, currency).
    Several invoices also match those ledgers (3-way: bank+ledger+invoice).

  Pass 2 Fuzzy:
    BNK-016 vs LDG-016: same ref, amount off ~0.91% (bank fee).
    BNK-017 vs LDG-017: same amount, dates 2 days apart (settlement lag).

  Pass 3 Partial:
    BNK-018 vs LDG-018: bank paid 19500 vs ledger 19850 (short pay).

  Exceptions (examples):
    BNK-019  empty referenceId          → MISSING_REF
    BNK-020  ref not in ledger          → NO_MATCH
    INV-017  EUR currency               → CURRENCY_MISMATCH
    INV-018  empty referenceId          → MISSING_REF
    INV-019  same ref as already-matched row → DUPLICATE (intent)
    INV-020  future date far from ledger → DATE_WINDOW_EXCEEDED
    LDG-020  never matched by bank/invoice → ORPHAN_LEDGER

6.3 Combined arrays

  financeRecords = [...bankStatements, ...ledgerEntries, ...invoices]

6.4 groundTruth

  Map of bank/invoice id → expected ledger id, or null if it should be
  an exception. Used only on the built-in batch to compute “accuracy”.

  Example:
    'BNK-001': 'LDG-001'
    'BNK-016': 'LDG-016'     (fuzzy still counts as a correct match)
    'INV-018': null          (should be exception)

6.5 openingBalance = 142350.00
    Seed cash for the forecast engine.

6.6 batchMeta
    batchId RECON-2026-08-22, period Aug 1–20 2026, 60 records.

7. RECONCILIATION ENGINE — reconciliationEngine.ts
--------------------------------------------------------------------------------

This is the core algorithm. Public entry: runReconciliation(input?).

7.1 Types it produces

  MatchStatus = Exact | Fuzzy | Partial | Exception | Pending
  MatchPass   = 1 | 2 | 3 | null

  ExceptionCode:
    AMOUNT_MISMATCH
    MISSING_REF
    DUPLICATE
    DATE_WINDOW_EXCEEDED
    CURRENCY_MISMATCH
    NO_MATCH
    ORPHAN_LEDGER

  SUGGESTED_ACTION — human text per exception code
    (e.g. MISSING_REF → get remittance advice; DUPLICATE → hold payment)

  MatchResult — one row of output:
    record, matchedLedgerId, matchedLedger,
    status, pass,
    exceptionCode, exceptionReason, suggestedAction,
    delta (absolute $ difference vs ledger),
    deltaPct,
    confidence 0–100,
    isThreeWay (bank + ledger + invoice same group)

  PassStats — counts per pass
  ReconciliationReport — totals, rates, lists, accuracy, runTimeMs

7.2 Helper: daysBetween(dateA, dateB)
  Absolute calendar days between two YYYY-MM-DD strings
  using Date.getTime() difference / 86400000.

7.3 Helper: pctDiff(a, b)
  |a-b| / b. If b is 0, returns 100 (avoid divide by zero).

7.4 classifyException(record, ldgMap, alreadyMatched)

  Called when Pass 1/2/3 all fail. Order of checks:

  1. If referenceId is blank/whitespace → MISSING_REF
  2. Look up ledger by that referenceId.
  3. If ledger exists AND already matched → DUPLICATE
  4. If record.currency !== 'USD' → CURRENCY_MISMATCH
       NOTE: the demo data is mostly INR. Depending on version, this
       check may fire for all INR rows that failed earlier passes, or
       the engine may treat INR as the working currency. Read the live
       file if you change currency rules.
  5. If ledger exists and |date diff| > 5 days → DATE_WINDOW_EXCEEDED
  6. If ledger exists and amount % diff > 1% → AMOUNT_MISMATCH
  7. Else → NO_MATCH (ref not in ledger, or leftover case)

7.5 runReconciliation(input?)  — step by step

  Optional input: { bankStatements, ledgerEntries, invoices }
  If omitted, uses financeData defaults (the 60-row batch).

  a) Start a timer with performance.now().

  b) Index ledger:
       ldgByRef: Map referenceId → FinanceRecord
       ldgById:  Map id → FinanceRecord
     Only ledgers with a non-empty referenceId go into ldgByRef.
     If two ledgers share a ref, the last one wins (Map.set overwrite).

  c) allSubjects = bankStatements + invoices
     Ledger is NOT in this loop; it is the thing we match TO.
     Orphans are found later.

  d) For EACH bank or invoice record:

     Pass 1 Exact:
       ledger found by same referenceId
       AND same currency
       AND |amount difference| < 0.01
       → status Exact, pass 1, confidence 100, delta tiny
       isThreeWay: if this row is an INVOICE and some BANK row also
       points at the same ledger id.

     Pass 2 Fuzzy (only if Pass 1 failed):
       ledger found, same currency
       AND amount within 1% (pctDiff <= 0.01)
       AND dates within 2 days
       → Fuzzy, pass 2
       confidence ≈ 95 - deltaPct*200
       suggestedAction: confirm bank fee or settlement lag

     Pass 3 Partial (only if Pass 2 failed):
       ledger found, same currency
       AND amount off by more than 1% AND less than 20%
       → Partial, pass 3, exceptionCode AMOUNT_MISMATCH
       confidence ≈ 70 - deltaPct*100
       suggestedAction: raise debit memo for the delta

     Else Exception:
       classifyException(...)
       confidence 0, no matched ledger

     matchedLedgerIds / ledgerMatchCount track which ledgers were used.

  e) Orphan pass:
     For each ledger whose id never appeared in ledgerMatchCount:
       Exception ORPHAN_LEDGER (no bank and no invoice touched it)

  f) exceptionList = rows with status Exception OR Partial
     (partials are treated as work-queue items)

  g) Accuracy vs groundTruth:
     Built-in batch: for each groundTruth entry, find the result by
     record id. If expected ledger is null, Exception is “correct”.
     If expected ledger id equals matchedLedgerId, match is “correct”.
     Custom CSV: code may skip real GT and use a placeholder accuracy
     (e.g. ~98%) because there is no labelled truth file.

  h) Totals:
     matchRate     = (exact + fuzzy) / totalAttempts * 100
                     totalAttempts = bank count + invoice count
     partialRate   = partials / totalAttempts * 100
     exceptionRate = exceptions / totalAttempts * 100
     clearedAmount = sum of ledger amounts for Exact+Fuzzy
     openAmount    = sum of exceptionList record amounts
     threeWayMatches = count of isThreeWay
     passStats     = running totals after each pass
     runTimeMs     = elapsed milliseconds

  i) Return ReconciliationReport.

Important design notes:

  - Matching is keyed almost entirely on referenceId. Names and
    descriptions are NOT used to match.
  - First ledger with that ref in the Map is the only candidate.
    True 1-to-many matching (one invoice, many payments) is not modelled.
  - Pass 1 does not check dates. A same-amount same-ref pair matches
    even if dates are far apart (those far-date cases may never reach
    DATE_WINDOW_EXCEEDED).
  - Duplicate detection depends on alreadyMatched; if that set is not
    updated in the exact/fuzzy/partial branches, DUPLICATE may rarely
    fire. Worth reading the live file if you rely on duplicate demos.

8. ML ANOMALY SCORER — mlScorer.ts
--------------------------------------------------------------------------------

Not a neural net and not Isolation Forest despite some UI copy. It is a
weighted feature score in JavaScript.

Public entry: runMLScoring(records = financeRecords)

8.1 buildBatchStats(records)

  Sort amounts.
  mean  = average amount
  std   = sqrt(variance); if 0, use 1 so z-score is defined
  median, p10, p90 (10th and 90th percentile amounts)
  counterpartyFreq[name] = how many rows use that name
  dateFreq[date]         = how many rows share that date
  refFreq[referenceId]   = how many rows share that ref (non-blank)

8.2 scoreRecord(record, stats)

  F1 Amount z-score (max 35 points):
    z = (amount - mean) / std
    amountDev = min(35, |z| * 12)

  F2 Reference quality (max 30):
    no ref        → quality 0   → 30 points of risk
    duplicate ref → quality 0.3 → 21 points
    unique ref    → quality 1   → 0 points

  F3 Currency (0 or 20):
    currency !== 'USD' → 20 points
    (INR demo rows all get this if USD is the “safe” currency)

  F4 Counterparty rarity (max 10):
    1 occurrence  → 10
    2             → 7
    3–4           → 3
    5+            → 0

  F5 Date clustering (max 5):
    share = rows-on-this-date / batch size
    contrib = min(5, share * 50)
    Many rows on one day slightly raises score.

  F6 Amount extremity (max 10):
    above p90 or below p10, scaled how far beyond the percentile.

  rawScore = sum of contributions, capped at 100.

  Risk bands:
    < 21  Normal
    < 46  Elevated
    < 71  High
    else  Critical

  modelConfidence: 60 + 6 per “active” feature, cap 95.
  explanation[]: English bullets for the features that fired.

8.3 runMLScoring

  buildBatchStats → score every record → Map by recordId
  highRiskCount = score > 45
  criticalCount = riskLevel Critical
  anomalyRate   = highRisk / n
  averageScore
  topAnomalies  = top 5 by score
  modelVersion / algorithm labels for the UI
  runTimeMs

9. CASH FORECAST — cashForecast.ts
--------------------------------------------------------------------------------

Public entry: buildForecast(report: ReconciliationReport)

Idea: take cleared money and open AR/AP from reconciliation and spread
them across 7 future banking days.

Constants:

  SETTLE_WEIGHTS = [0.35, 0.28, 0.18, 0.12, 0.07]
    Cleared inflows arrive 35% T+1, 28% T+2, … through T+5.

  DOW_MULT = [0.10, 1.00, 1.05, 0.95, 1.00, 0.80, 0.15]
    Index = JS weekday (0=Sun). Weekends almost no volume.

Helpers:

  addDays(base, n) — add n UTC days to YYYY-MM-DD
  labels(dateStr)  — { label: 'Mon, Aug 25', shortLabel: 'Aug 25', dow }

Logic of buildForecast:

  1. cleared = report.clearedAmount

  2. Open AR (money still expected in):
     CREDIT exceptions (not orphan) * 50% assumed recovery
     PLUS Partial CREDIT deltas (short-pay leftover)

  3. Open AP (money going out):
     sum of DEBIT exception amounts

  4. Routine daily flow:
     avgTx = cleared / max(exact+fuzzy, 1)
     routineInflow  = avgTx * 1.8
     routineOutflow = avgTx * 1.4

  5. BASE date hardcoded '2026-08-21' (Thursday in the demo calendar).
     Day i=0..6 is BASE+(i+1).

  6. Each day:
     settledAmount = cleared * SETTLE_WEIGHTS[i] for i<5 else 0
     AR recovery   = from day 3 onward, 25/30/25/15/5% of openAR
     AP outflow    = first 4 days 40/30/20/10% of openAP
     routine in/out scaled by weekend/weekday multiplier
     net = in - out
     running balance starts at openingBalance from financeData
     confidence = max(40, 95 - i*10)  (less sure further out)

  7. Peak / trough closing balances, expected 7-day close,
     coverageRatio = trough/peak, netChange vs opening.

This is a teaching model, not a treasury system. Weekend multipliers and
the base date are fixed.

10. TAX LINE MATCHER — taxLineMatcher.ts
--------------------------------------------------------------------------------

Public entry: runTaxLineMatcher(report)

Walks every MatchResult in report.results and assigns a tax category.

10.1 classifyTaxCategory(row)

  If currency !== USD          → Foreign Withholding
  If type DEBIT:
    Vendor Payment             → Cost of Revenue
    else                       → Operating Expense
  If Exception and no ledger   → Unclassified
  SaaS / License / Enterprise / AR → Revenue
  Consulting / Services / Support  → Revenue
  Project Payment > 10000          → Capital Expenditure
  Project Payment otherwise        → Revenue
  Wire Transfer CREDIT             → Revenue
  Wire Transfer DEBIT              → Operating Expense
  else                             → Unclassified

10.2 assessTaxRisk(row, taxCat)

  Unclassified                         → High
  Exception with amount > 5000         → High
  Foreign Withholding                  → Medium (check treaty)
  Partial match                        → Medium (delta affects tax)
  Amount > 20000                       → Medium
  else                                 → Low

10.3 determineJurisdiction(row)

  EUR currency            → EU
  GBP                     → UK
  name contains GmbH/AG   → DACH
  name contains Ltd       → UK
  else                    → US-Federal

10.4 Rates and GL codes (simplified teaching schedule)

  Revenue             21%   GL 4000-REV
  Cost of Revenue      0%   5000-COR  (deductible)
  Operating Expense    0%   6000-OPX  (deductible)
  Capital Expenditure  7%   1500-CAP
  Exempt               0%   9000-EXM
  Foreign Withholding 15%   2300-FWT
  Unclassified        21%   9900-UNC  (conservative)

  taxAmount = amount * rate (rounded to cents)
  isDeductible = COGS or OpEx

10.5 Totals

  Gross revenue = Revenue + Unclassified amounts
  Deductions = deductible line amounts
  Net taxable = gross - deductions
  Estimated liability = sum of taxAmount
  Effective rate = liability / gross
  automationRate = % not Unclassified
  categoryBreakdown and jurisdictionBreakdown for charts

11. SETTLEMENT Q&A — settlementQA.ts
--------------------------------------------------------------------------------

Public: askAgent(question, report) → QAAnswer

This is NOT ChatGPT. It is regex + fallbacks.

QAAnswer fields:
  question, thinkingProcess[] (fake “reasoning” bullets),
  answer (markdown-ish text), recommendation?,
  data (matching MatchResults or null),
  confidence 0–100, category, responseTimeMs

askAgent steps:

  1. Trim question.
  2. Walk intents[] in order. First regex that matches wins.
     Intents include:
       match rate / pass 1 2 3 / performance
       open position / cleared / outstanding
       tax / withholding / GL
       cash forecast / liquidity / T+1
       amount mismatch / short pay
       duplicate
       missing ref
       currency / FX / EUR / GBP
       ML / anomaly / high risk
       all exceptions / unresolved
     Handlers call runTaxLineMatcher, buildForecast, runMLScoring as
     needed and format numbers.

  3. If no intent: try record-id regex
       e.g. B1-BNK-016 or INV-042
       Look up in report.results and describe that row.

  4. If still nothing: words longer than 3 chars searched inside
     counterparty names. First hit returns that vendor’s rows.

  5. Else a help message listing example questions.

SAMPLE_QUESTIONS is a string array used as clickable chips in the UI.

Limitation: first matching regex wins. A question that contains both
“tax” and “forecast” will only hit whichever pattern is listed first.

12. CSV SERVICE — csvService.ts
--------------------------------------------------------------------------------

BATCH_INFO:
  Five named demo worlds (Enterprise Q1, Global FX Q2, E-commerce Q3,
  SaaS Q3, Year-end Q4), each with a filename and month.

COMPANIES_SETS: 10 company names per batch (different industries).
CATEGORIES: the Category union values, rotated round-robin.

12.1 generateBatchSet(batchNum 1..5)

  Builds ~500 records:

  170 LEDGER rows
    id B{n}-LDG-001 …
    refs like SET1-PAY-2026-0801-1
    last ledger (i=170) gets ORPHAN-REF-999 so one orphan exists
    mostly CREDIT, every 18th DEBIT
    amounts from a deterministic formula (not random) so reloads match

  165 BANK rows, each paired with ledger[i-1], then mutated:
    i%25==0  blank ref, “Unknown Remitter”
    i%30==0  unmatched fake ref
    i%12==0  amount * 0.991 (fee)     → fuzzy / partial
    i%15==0  date ±1–2 days           → fuzzy date window
    i%19==0  amount * 0.95            → short pay / partial

  165 INVOICE rows, similar mutations:
    missing ref, EUR/GBP, amount * 1.12, next-month date, date -3 days

  Returns { all, bank, ledger, invoices, filename, name }

12.2 generate500Records()
  Alias for generateBatchSet(1).

12.3 recordsToCSV(records)
  Header row: id,source,referenceId,counterparty,amount,currency,date,
  description,type,category
  Quotes fields that may contain commas; doubles internal quotes.

12.4 parseCSV(csvText)
  Split lines, require header + data.
  Header names are flexible (id / recordid, referenceId / ref, etc.).
  Each data line → FinanceRecord.
  source inferred: BANK if word BANK, INVOICE if INV, else LEDGER.
  currency: EUR, GBP, else USD (note: generated batches use INR;
  uploaded files labelled INR may be stored as USD depending on this
  mapping — important if you debug FX).
  type: DEBIT or CREDIT.
  Returns { records, bank, ledger, invoices }.
  Throws if empty.

12.5 splitCSVLine(line)
  Character loop: toggle quotes, treat "" as escaped quote, split on
  comma only when not inside quotes.

generateBatches.js (Node, not imported by the React app):
  Writes the five CSVs into public/ so you can download or serve them
  as static files.

13. PAGES — WHAT EACH SCREEN DOES
--------------------------------------------------------------------------------

13.1 Landing.tsx
  Marketing page. Stacks: Navbar, Hero, TrustMetrics, Problem, Features,
  HowItWorks, WhyChoose, FAQ, FinalCTA, Footer. Uses landing.css.
  No finance engine. CTA links typically go to #/dashboard or recon.

13.2 Dashboard.tsx
  Shell: TopNav + Sidebar + main.
  Reads FinanceContext. If no report yet, copy says upload CSV.
  If report exists, banner shows match rate, cleared $, exceptions,
  accuracy, ML flagged count.
  Then MetricCards, RiskTrendChart, TransactionTable.

13.3 ReconciliationPage.tsx
  Main product screen.
  ReconciliationRun at top (ingest + animated 3-pass run).
  On complete: saves report into page state AND FinanceContext.
  Then MatchSummary, ExceptionList, ML panel, Settlement Q&A,
  CashForecastChart, TaxLineMatcherPanel.
  Links to Exceptions page with current exception count.

13.4 FinancePage.tsx
  Older/alternate layout of the same panels (Finance Controller title).
  Not always in the hash router; ReconciliationPage is the live route.
  ReconciliationRun onComplete only sets local report unless wired to
  context (check live file).

13.5 ExceptionsPage.tsx
  Uses ctx.report, or runReconciliation() on the built-in 60-row batch
  if the user never ran a batch (so the page is never empty).
  EXCEPTION_DESCRIPTIONS maps each code to label, suggested action,
  badge colors.
  Filter by code (ALL or one code).
  Search by id / counterparty / description (case-insensitive).
  toggleResolved(id) is local UI only (Set of ids) — not written to a
  server or to FinanceContext.
  Lists exceptionList rows with amounts, deltas, actions.

13.6 RecordDetailsPage.tsx
  Hash can include id=, e.g. #/record-details?id=B1-BNK-016
  Selects that row from report.results, else first row.
  Combines:
    match result (status, delta, suggested action, matched ledger)
    ML score from scoreMap
    tax line item
  Local-only actions (lost on refresh):
    resolvedStatus, assignedAnalyst, auditNotes
  ANALYSTS list for assign modal.
  Empty state if no rows: go to Reconciliation.

13.7 CashForecastPage.tsx
  buildForecast(report or default recon).
  Shows CashForecastChart and related composition UI.
  Horizon toggle (e.g. 7 days) may only change display, not the engine
  (engine is hard-coded to 7 days).

13.8 ReportsPage.tsx
  Recap of last run (or default batch).
  Dummy RECENT_AUDIT_LOGS for “certified” history.
  Export helpers typically:
    JSON dump of the reconciliation report
    CSV of result rows (id, amounts, status, exception, action)
    CSV of tax lines

17. HOOK — useCountUp.ts
--------------------------------------------------------------------------------

useCountUp(end, duration=1000)

  If prefers-reduced-motion: jump to end immediately.
  Else requestAnimationFrame loop:
    progress = elapsed / duration, clamped 0..1
    eased = 1 - (1-progress)^3   (ease-out cubic)
    displayed = round(end * eased)
  Cleanup cancels the frame.
  Used so KPI numbers “count up” instead of popping in.

19. WHAT IS REAL VS DEMO
--------------------------------------------------------------------------------

Real (runs in your browser, reproducible):
  3-pass matching rules
  Exception classification
  Weighted ML-like score
  Tax mapping rules
  7-day cash arithmetic
  CSV parse/generate
  Hash routing and React UI

Not real:
  No bank feed, ERP, or invoice API
  No database; refresh can lose local exception “resolved” flags
  Settings sliders do not drive the engine
  AI Assistant is regex, not a language model
  ML is not Isolation Forest / not trained
  Tax rates are a simplified teaching schedule, not a tax engine
  Audit “sign-off” and “certified” logs are dummy rows
  Accuracy on uploaded CSVs may be a placeholder, not labelled truth
